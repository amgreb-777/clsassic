# Classic · Закупівля

Веб-платформа, що відтворює й розширює таблицю **«Шаблон_меню.xlsx»**: обираєте страви для заходу, вказуєте кількість порцій, і платформа формує **список закупівлі продуктів** (брутто/нетто) за технологічними картами.

- **База даних:** Supabase (проєкт `clsassic`, `https://gnsgayyhmajofcjlilbq.supabase.co`)
- **Фронтенд:** React + Vite + TypeScript (`web/`)
- **Деплой:** GitHub Pages (`.github/workflows/deploy.yml`)

## Як працювала таблиця

| Аркуш | Що містить | Логіка |
|---|---|---|
| **Довідник Продуктів** | 265 назв продуктів | єдині назви, щоб закупка сумувалась коректно |
| **МенюЗамовлення** | 229 страв: назва, вага 1 порції | користувач вписує кількість; `Загальна вага = кількість × вага порції` |
| **Склад Блюд** | 1 498 рядків: страва → продукт, брутто й нетто на 1 порцію | `Кількість = VLOOKUP(страва, Меню)`, `Разом = брутто/нетто × кількість` |
| **ЗАкупка** | зведена таблиця | `SUM(брутто)`, `SUM(нетто)` по кожному продукту |
| Закупи (прихований) | стара версія через `SUMIFS` | — |

Доступ: **лише для команди**. Список дозволених email зберігається в таблиці `team_members` (ролі `admin` / `member`), ним керують на сторінці «Команда».
- Реєстрацію з email поза списком блокує тригер на `auth.users`.
- Дані (RLS) бачать і змінюють лише члени команди; людина, яку прибрали зі списку, одразу втрачає доступ.
- Додавати/видаляти учасників можуть лише адміністратори; себе видалити не можна.
- **Без листів:** самостійної реєстрації немає — адміністратор створює акаунт колезі з тимчасовим паролем (`admin_create_account`) і задає новий тимчасовий пароль, якщо хтось забув свій (`admin_set_password`, завершує всі сесії користувача). При вході з тимчасовим паролем сайт вимагає встановити власний (`app_metadata.must_change_password`).
- Анонімний ключ у фронтенді не дає доступу до даних.

### Що виправлено/уточнено під час імпорту

- **Штучні продукти.** У 150+ рядках «Брутто» насправді означає **кількість штук**, а «Нетто» — грами (напр. «Креветки (шт)» 1 / 10, «Томати чері» 0,5 / 5). У таблиці такі значення сумувались разом із грамами. У базі для них заведено одиницю `шт` (і `л` для ігристого), тож у закупці це окремі рядки: «Томати чері — 300 шт» і «Томати чері — 1,2 кг».
- «Томати Чері» та «Томати чері» об'єднано в один продукт.
- Дубль страви «Міні вафлі з хамоном» у меню прибрано.
- Повторний рядок «Петрушка» в «Міністроне» об'єднано (6+6 г / 5+5 г), як і сумувала зведена таблиця.
- Регістр назв («карпаччо з буряка» ↔ «Карпаччо з буряка») зведено до однієї страви.
- Категорії страв (Салати, Брускети, Бокси…) проставлено автоматично за назвою; їх можна змінити в розділі «Страви».
- Рядки, де нетто > брутто для вагових продуктів (квасоля, рис, нут, локшина — після варіння), залишено як є, а в редакторі техкарти вони підсвічуються.

## Можливості сайту

1. **Замовлення.** Створення заходу (назва, дата, кількість гостей, статус, примітки), копіювання та видалення.
2. **Меню замовлення.** Каталог із пошуком і фільтром за категоріями; кількість порцій (кнопка «×гостей»), вага порції, загальна вага та вага на гостя. Автозбереження.
3. **Закупка продуктів.** Брутто (скільки закупити) і нетто по кожному продукту, у г або кг; у скількох і в яких стравах він використовується; позначки «куплено»; експорт у Excel (CSV) і друк.
4. **Склад по стравах.** Розкладка кожної страви: на 1 порцію та на всю кількість (аналог «Склад Блюд»), з експортом і друком.
5. **Страви.** Редагування технологічних карт: продукти, брутто/нетто, одиниці, вага порції, категорія, приховування з каталогу.
6. **Продукти.** Кожен продукт має категорію (відділ: Овочі, М'ясо, Сири…), фільтр і пошук за категоріями.
    Довідник: перейменування (одразу оновлюється в усіх стравах), категорія, видалення продуктів, що ніде не використовуються.
7. **Команда.** Учасники та їхній статус (активний / тимчасовий пароль / немає акаунта). Адміністратор створює акаунти з тимчасовим паролем, задає новий тимчасовий пароль («забув пароль»), змінює ролі, прибирає учасників.
8. **Змінити пароль** — кнопка у верхньому меню.

## Запуск локально

```bash
cd web
npm install
npm run dev
```

Ключі Supabase за замовчуванням прописані в `web/src/lib/config.ts` (це публічні ключі). Перевизначити їх можна через `VITE_SUPABASE_URL` і `VITE_SUPABASE_PUBLISHABLE_KEY`.

## Деплой (GitHub Pages)

1. У репозиторії: **Settings → Pages → Source: GitHub Actions**.
2. Злийте зміни в `main`: workflow збере `web/` і опублікує сайт на `https://amgreb-777.github.io/clsassic/`.
3. (Необов'язково) У Supabase: **Authentication → URL Configuration** → `Site URL` = адреса сайту. Платформа не надсилає листів, тож це потрібно лише на випадок, якщо пошту колись підключать.

## Харчова цінність (КБЖВ)

- У кожного продукту — ккал, білки, жири, вуглеводи на 100 г їстівної частини (`scripts/product_nutrition.py`, SQL — `supabase/product_nutrition.sql`). Джерела: USDA FoodData Central, довідник хімічного складу харчових продуктів (Скурихін), маркування для соусів і напівфабрикатів.
- Розрахунок — від ваги нетто з техкарти; для круп/бобових/локшини, де нетто — вага після варіння, береться суха вага (менша з брутто/нетто). Функція `public.ingredient_grams`.
- `dish_nutrition` — КБЖВ на 1 порцію страви; `order_nutrition(order_id)` — по стравах замовлення.
- На сайті: картка «Харчова цінність» у замовленні (усе замовлення, на 1 гостя, % добової норми за RI ЄС, розподіл енергії БЖВ), ккал у каталозі й меню, КБЖВ на порцію в техкарті та розкладці, редагування КБЖВ у «Продуктах».
- Не враховано: втрати й зміну маси при термообробці, олію для смаження, якщо її немає в техкарті.

## Ціни та собівартість

- **Ціни по магазинах** — таблиця `product_prices` (продукт × магазин): Сільпо, METRO, NOVUS, Auchan, MegaMarket. На сторінці «Продукти» (вид «Ціни магазинів») кожен магазин — окрема колонка з посиланням на товар; найнижча ціна підсвічена зеленим, магазин для розрахунку — золотим; колонка «Середня ціна» — середнє арифметичне цін магазинів, де продукт знайдено (без ручних), так само, як у режимі розрахунку «Середня по магазинах»; вона є і в Excel-експорті. Дані: `supabase/store_prices.sql`, `scripts/data/store_prices_2026-11-22.json` (METRO/NOVUS/Auchan/MegaMarket зібрано через публічний API zakaz.ua).
- **Документ замовлення** — кнопка «Документ замовлення» в замовленні відкриває меню заходу у фірмовому оформленні Classic Catering (логотип, назва, дата, кількість гостей, примітки, страви за розділами з виходом, кількістю порцій і вагою, підсумки: вага й калорійність на гостя). Перемикач «Собівартість» додає собівартість порції, суму і собівартість меню (вимкнений за замовчуванням — документ можна віддавати клієнту). Кнопки: **Друк**, **PDF** (через вікно друку → «Зберегти як PDF», назва файлу підставляється автоматично) і **Excel** (той самий документ у .xlsx з оформленням, готовий до друку на A4).
- **Розділ «Ціни» (оновлення цін)** — сторінка `/prices` (пункт меню «Ціни»). Ціни METRO, Сільпо, NOVUS, Auchan і MegaMarket оновлюються **автоматично щопонеділка о 8:00 за Києвом** (pg_cron: `price-refresh-weekly`) або кнопкою **«Оновити зараз»** (адміністратор). Оновлення йде на сервері **чергою за кілька проходів**: `start_price_run` створює запис у `price_runs` і чергу `price_run_items` (товар × магазин); щохвилини `price-refresh-tick` викликає Edge Function `refresh-prices` (`supabase/functions/refresh-prices`, авторизація заголовком `x-cron-key` із `private.app_secrets`), яка за прохід (~100 с) перевіряє товари з черги — магазини zakaz.ua двома потоками з паузою, Сільпо окремо; на відповідь «забагато запитів» товар повертається в чергу з паузою 1–5 хв (до 8 спроб). Сторінку можна закрити — оновлення продовжиться. Після останнього проходу `finish_price_run` перераховує ціну для розрахунку, робить знімок у історію й формує звіт. Ціна: звичайна (без акцій); нова ціна за кг/шт = стара × (нова ціна упаковки / `pack_price`); зміна понад ×2,5 вважається підозрілою (інше фасування) і не застосовується; товари без наявності позначаються. Ручні ціни не змінюються.
  - **Історія цін** — `price_history`: кожна перевірена ціна (продукт × магазин, з попередньою ціною, наявністю, ціною упаковки) і знімок ціни для розрахунку («Розрахунок», з магазином-джерелом) після кожного оновлення. Початкова точка — ціни від 22.11.2026.
  - **Звіти** — вкладка «Звіти оновлень»: кожне оновлення з датою, способом запуску (за розкладом / вручну), тривалістю й кількістю проходів; перевірено, змінилось, змінилось у розрахунку, підозрілі, без відповіді; по магазинах; список змін ціни для розрахунку; найбільші зміни в магазинах; підозрілі.
  - **Динаміка цін** — вкладка «Динаміка цін»: для кожного продукту ціна для розрахунку, зміна з минулого оновлення і за весь час, міні-графік; по натисканню — графік і таблиця цін у кожному магазині за датами оновлень (сірим — немає в наявності).
- **Ціна для розрахунку** — `products.price_*`, її задає `apply_price_store(store)` з обраного магазину (або `'Середня'`), поточний вибір — `app_settings.price_store` (зараз **METRO**). Адміністратор перемикає джерело в «Продуктах» → «Ціна для розрахунку». Якщо продукту немає в обраному магазині або там його **немає в наявності**, для розрахунку береться **мінімальна ціна серед інших магазинів, де товар є в наявності** (якщо такого магазину немає — лишається ціна обраного); на сторінці такий магазин позначено «у розрахунку». **Ручна ціна має перевагу над усіма магазинами**: вона зберігається окремою колонкою «Вручну» з датою внесення (видно в клітинці «від ДД.ММ.РРРР»); щоб повернути ціну магазину, достатньо очистити поля ціни. У техкарті страви плитка «Собівартість» теж показує вартість порції в інших магазинах, за середньою ціною і оптимальний кошик (оновлюється під час редагування складу). Такі ж плитки є на вкладках «Меню» і «Склад по стравах» (страв і порцій, собівартість меню з цінами в інших магазинах, на 1 гостя, вага) — рахуються з техкарт обраних страв і оновлюються одразу при зміні меню. У плитці «Вартість закупки» під сумою для розрахунку — вартість цієї ж закупки в інших магазинах («без N», якщо чогось немає; найдешевший магазин, де є все, — зеленим), за середньою ціною і «оптимальний кошик». У закупці кнопка **«Ціни магазинів»** вивантажує .xlsx: аркуш «Закупка» (кожна позиція — кількість, ціна й сума в кожному магазині та за середньою ціною магазинів, сума для розрахунку, найдешевший магазин з наявних; підсумки формулами, позиції без ціни й без наявності, на 1 гостя) і аркуш «Порівняння магазинів» (уся закупка в кожному магазині, чого там немає, і «оптимальний кошик» — кожна позиція там, де найдешевше з наявних). Кнопка **Excel** у «Продуктах» вивантажує .xlsx з цінами всіх магазинів: аркуш «Ціни» (продукт × магазин, ₴/кг і ₴/шт, ціна для розрахунку та її джерело, найдешевший магазин, клікабельні ціни) і аркуш «Товари в магазинах» (назва товару, фасування, наявність, дата, посилання); бібліотека ExcelJS вантажиться лише під час експорту. Список продуктів сортується натисканням на назву будь-якої колонки (повторне натискання — зворотний порядок, порожні значення завжди в кінці); на телефоні — через список «Сортування».
- У кожного продукту — `price_kg` (грн/кг, для рідин — грн/л) і `price_pcs` (грн/шт), а також магазин, назва товару, фасування, посилання й дата збору (`price_at`). SQL з цінами — `supabase/product_prices.sql`, сирі результати пошуку — `scripts/data/silpo_prices_2026-11-22.json`.
- Ціни зібрано 22.11.2026 з Сільпо (доставка по Києву, включно з розширеним асортиментом) через коннектор Сільпо; 11 продуктів, яких немає в Сільпо, — з METRO, NOVUS, Auchan і MegaMarket (zakaz.ua, Київ). Береться **звичайна** ціна (без тимчасових акцій), щоб калькуляція не стрибала; акційна ціна, якщо була, записана в примітці.
- Вартість рахується від **брутто** (те, що треба купити): «г» → брутто/1000 × ₴/кг; «шт» → брутто × ₴/шт (або нетто/1000 × ₴/кг, якщо ціни за штуку немає); «л» → брутто × ₴/л. Функція — `ingredient_cost`, собівартість порції — view `dish_cost`.
- На сайті: ціна в «Продуктах» (з фільтром «Без ціни» і ручним редагуванням — тоді джерело стає «Вручну» з поточною датою), собівартість порції в каталозі страв і техкарті (вартість кожного рядка), вартість кожної страви й підсумок «Собівартість / На гостя» в меню замовлення, ціна і вартість кожної позиції, сума по відділах і загальна вартість у списку закупки (і в Excel).

## Категорії продуктів

Категорії (відділи) задані в `scripts/product_categories.py`; SQL для бази — `supabase/product_categories.sql`.
У закупці продукти групуються за відділами в порядку обходу магазину (перемикач «за відділами»).

## Оновлення даних із таблиці

```bash
python3 scripts/import_xlsx.py "Шаблон_меню.xlsx" > supabase/seed.sql
```

Скрипт ідемпотентний (`on conflict … do update`), тож його можна повторно застосувати до бази. Схема лежить у `supabase/migrations/`.
